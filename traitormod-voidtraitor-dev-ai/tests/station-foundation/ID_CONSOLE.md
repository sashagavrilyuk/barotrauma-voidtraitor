# Консоль управления ID-картами

Предмет `vt_station_access` находится на тестовой станции рядом с местом появления экипажа. В нём два слота: карта авторизации и редактируемая карта. Вставка переносит настоящую карту из инвентаря; извлечение возвращает её в инвентарь или кладёт рядом, если места нет.

Карта авторизации ограничивает как выдачу, так и снятие доступов. Например, инженер не может выдать арсенал или снять уже имеющийся доступ в арсенал. Пресет меняет только доступные ему права; остальные права редактируемой карты сохраняются. Название профессии не выдаёт доступ само по себе.

С клиентским Lua открывается отдельная панель размером до 800×530 пикселей, ограниченным размером экрана. Доступы размещаются в четырёх столбцах; новые записи из конфигурации заполняют ту же сетку. Нижние четыре кнопки одинаковы по ширине, нижняя подсказка располагается у края окна. Выбор консоли проверяется каждый кадр; запрос отправляется сразу и при необходимости повторяется через 0,05 секунды. Сведения можно получить до штатного подтверждения выбора предмета, но лишь рядом с доступной консолью. Вставка, извлечение и редактирование по-прежнему требуют подтверждённого выбора. «Закрыть» также отправляет штатное действие Deselect, чтобы консоль не открывалась снова после сетевой коррекции. Штатный интерфейс этого предмета скрыт.

Без клиентского Lua данные карт показываются в информационном терминале, действия выбираются в отдельном штатном меню кнопкой «Карты и доступы». Меню не дублирует полный текст терминала. Имя и должность вводятся в полях консоли: закройте меню действий, затем нажмите «Сохранить имя и должность».

## Настройка доступов

Список доступов и штатные пресеты по умолчанию находятся в `Lua/config/idconsole.lua`. Этот файл **не редактируйте при обычной настройке**: изменяйте `config.IdConsole` в пользовательском `Lua/config/config.lua` (создаётся автоматически, сохраняется при обновлениях). Правила загружаются через общий `Traitormod.Config`. Для нового права добавьте `{ Tag = "vt_access_newroom", Name = "Новая комната" }` в `config.IdConsole.Access` (либо локализованный ключ `Name` в `Lua/language/russian/idconsole.lua`). Пресеты с `AllAccess = true` получают полный **актуальный** список, включая добавленные пользователем теги. Начальные карты экипажа получают пресет в режиме Station.

Пример для `Lua/config/config.lua`:

```lua
table.insert(config.IdConsole.Access, { Tag = "vt_access_laboratory", Name = "Лаборатория" })

table.insert(config.IdConsole.Presets, {
    Id = "engineering_laboratory",
    Name = "Инженер лаборатории",
    Tags = {
        "vt_access_maintenance", "vt_access_engineering",
        "vt_access_reactor", "vt_access_engineering_stock",
        "vt_access_laboratory", "vt_access_cargo"
    },
})

-- Изменить уже существующий инженерный пресет:
for _, preset in ipairs(config.IdConsole.Presets) do
    if preset.Id == "engineer" then
        table.insert(preset.Tags, "vt_access_medical")
        break
    end
end
```

Пресет — это **любой набор комнат**, он не обязан совпадать с профессией. `Id` — уникальное имя пресета; `Name` — отображаемая подпись (текст или ключ локализации); `Tags` — полный желаемый список доступов. `JobId` необязателен и задаётся только если нужно поменять **штатный** `IdCard.OwnerJobId` на существующий идентификатор профессии. Без `JobId` пресет не меняет этот идентификатор. Доступы, которых нет на карте авторизации, пресет не выдаёт и не удаляет.

Для двери используйте:

```xml
<Door>
  <RequiredItem items="vt_access_newroom" type="Picked" characterinventoryslottype="Card" msg="ItemMsgUnauthorizedAccess" />
</Door>
```

Редактируемые теги должны находиться на экземплярах карт, не в `ItemPrefab.Tags`: игра всегда возвращает теги префаба. Старые теги карт сохранены для совместимости; двери, использующие старые `id_*`/медицинские теги, надо отдельно перевести на новые станционные доступы. В тестовой станции дверь `vt_station_reactordoor` проверяет `vt_access_reactor`.

При появлении настоящего капитана его исходная карта получает серверную метку `vt_station_original_captain_id`. Цель предателя `StealCaptainID` в Station требует именно такую карту, а не любую карту с изменяемым `OwnerJobId = captain`; в остальных режимах прежняя проверка сохранена. Консоль не может назначить или скопировать эту метку.

Имя записывается в `IdCard.OwnerName` и тег `name:`. Выбор существующего игрового пресета меняет `OwnerJobId` и `jobid:`. Произвольная должность хранится в `vt_jobtitle:` и описании карты: штатная Barotrauma не поддерживает произвольное название в поле `OwnerJobId`. Эти поля не передаются обычным событием изменения свойства; сервер обновляет клиентскую копию штатными событиями удаления/появления, затем отправляет состояние карты. Серверный предмет, ID, состояние, внешность владельца и ссылки заданий сохраняются. Если предыдущее обновление карты ещё не отправлено, следующее изменение имени/должности отклоняется с короткой подсказкой повторить сохранение. Это предотвращает слияние событий состояния в штатной очереди. Сохранение без изменений не переписывает исходное описание.

## Ручная проверка

1. Начните Station на `VoidTraitor Station Test`. У консоли лежат карты «Глава персонала», «Инженер», «Тестовая карта».
2. Вставьте первую и тестовую карты; примените пресет инженера, измените имя и должность, извлеките карту. Проверьте данные и дверь реакторной. При проверке снятого доступа уберите из инвентаря другие карты с этим доступом: штатная Barotrauma учитывает все имеющиеся карты.
3. Вставьте инженерную карту как авторизацию. Проверьте выдачу/снятие реакторной, недоступность арсенала и сохранение чужих прав при пресете или «Убрать все доступные».
4. Проверьте подтверждение удаления, сброс черновика, обе кнопки извлечения, смену карт, уход от консоли и повторное открытие.
5. Повторите без выполнения клиентского Lua: меню, отдельные права, пресеты, поля имени/должности. С клиентским Lua проверьте выпадающие списки поверх панели и отсутствие штатного терминала.
6. Проводка консоли не должна открываться ни руками, ни через клиентское меню; компонент заблокирован и не выбирается.

`run.ps1` проверяет синтаксис Lua, серверные запреты и повтор открытия после отклонённого первого запроса в изолированной модели. Игровую проверку он не заменяет. Серверу требуется LuaCsForBarotrauma, клиентам — XML-пак.

Повторная проверка 12.10.2026: реальная Lua-панель содержит четыре столбца; все 11 названий помещаются в их текстовые поля, от нижней подсказки до края окна 14 пикселей. При намеренно не подтверждённом сервером выборе предмета локальная панель появилась за один кадр (около 17 мс); действие из такой сессии отклонено, native-открытие сохранило строгую проверку выбора. Это локальный замер, не гарантия времени открытия в интернете. Проверены реальные серверные голосования: карта станции без отмеченной миссии не включает станционные кандидаты; миссия станции на обычной подлодке включает их; изменение миссии отменяет несовместимое голосование. В этом повторном цикле проверялись элементы и размеры настоящего GUI; новый снимок GPU не получен.

Лаборатория 1.13.4.0: проверены реальные Lua GUI callbacks, пресет инженера, имя/свободная должность и свойства карты на клиенте, одинаковая ширина кнопок, скрытие штатного HUD, слой списка профессий, сброс/подтверждение/извлечение, дверь с изменёнными тегами. Намеренно отклонённый первый запрос открытия восстановился повтором за 0,55 секунды. Для штатного клиента используется отдельная лабораторная копия с отключённым выполнением клиентских Lua-скриптов и чтением обычных GUI/пакетов; это не отдельная проверка чистой vanilla DLL. В ней реальными кнопками проверены вставка, пресет и сохранение имени/должности: карта с состоянием 33 сохранила его на клиенте после обновления. Сохранение неизменённых полей сохранило исходное описание. На настоящей очереди сервера проверены отклонение второго обновления в том же кадре и обновления при неотправленном состоянии, допустимость изменения только прав и успешный повтор после отправки событий.
